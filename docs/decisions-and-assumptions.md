# Decisions and Assumptions

## Decisions made
- Project name: Student Recruitment Portal
- Pathway: Software Developer
- Main target: students and parents/carers
- Core product: a public-facing web app
- MVP will include information content, triage logic, and a chatbot
- No user login or account system for the MVP
- No database persistence required for the initial version

## Assumptions
- The team does not have access to the original hackathon prototype
- The project will be built from scratch
- The deadline is extremely tight, so scope must stay minimal and focused
- The app should prioritise clarity and usefulness over complexity

## AI approach
- The project may use an open-source or lightweight LLM if budget is limited
- Chatbot answers should be based on source material rather than generic assumptions

## Assessment alignment
The build should clearly show:
- user-centred design
- technical architecture
- testing and validation
- critical evaluation of the project process
